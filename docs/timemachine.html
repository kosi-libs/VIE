Where the probe plugs into vie-mvi

The probe uses only the public middleware contract and the ViewModel's public API. Each hook was chosen for a property the timeline depends on.

vie-mvi entry pointProbe uses it toConsequence
middlewares, folded with foldRightSit last in the list, nearest the sourceIntents are seen as posted and signals as emitted, before another middleware filters or maps them. An intent dropped by another middleware is still reported.
interceptIntentsObserve intents with onEachOrder is exactly the order process handles them.
interceptSignalsObserve signals with onEachNever collects signalFlow, which would steal Effects from the view.
interceptModelsObserve every model with onEachRuns from construction, with or without a view, starting with the first model: every model in order, equal ones included. Only modelFlow, downstream of every middleware, conflates. Collects on the spot, never with flowOn.

viewModelScopeRun injectionsAn injection dies with its ViewModel. On a multi-threaded dispatcher, the probe's injected-object slots must be atomic.

Why a timeline can have holes

Four markers, four different causes. The inspector never guesses which messages are missing; it shows what the facts allow.

GapThe probe's queue overflowed. An observations-dropped row names the ViewModel and the count; it took the dropped messages' sequence slot, so there is no hole.TimeMachineOutbox.build

Notes from reading the code

Points that a reader of the README might not expect.

Equal models are observed. The probe observes models through interceptModels, whose flow carries every model update applies, including one that leaves the model equal, with no conflation. An injected model is therefore always observed and tagged, equal to the current one or not.
Sequences are assigned at send, not at observation. A dropped message takes no number, which is why a drop report can stand in its place without a hole, and why at is never used for ordering.
The acknowledgement is per connection. After an eviction, a frame from the old connection is still placed, but only the connection that carried a message acknowledges it; the probe's resend on the new connection is what clears it from inFlight.
A data object can steal a tag. Matching is by identity. A data object intent is a singleton, so an app-produced instance can be observed first and take the injected one's tag.
Nothing bounds sessions. Each run of an app in a debug loop leaves a disconnected session until the developer clears it. Per-ViewModel timelines are bounded; the number of ViewModels and sessions is not.
